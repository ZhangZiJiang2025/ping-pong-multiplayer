# 🏓 卓球ゲーム - 2人対戦

ブラウザで遊べる2人対戦の卓球ゲームです。インストール不要、URLを開くだけで遊べます。

---

## 🎮 遊ぶ人向け

### 遊び方

1. 公開されているURLをブラウザで開く
2. 名前を入力して「参加」ボタンを押す
3. 相手が来たら「スタート」ボタンを押す
4. 矢印キー ↑↓ でパドルを操作して5点先取で勝ち！

### ルール

- **操作**: 矢印キー ↑↓ でパドルを上下に動かします
- **勝利条件**: 5点先取で勝ち
- **難易度**: かんたん／ふつう／むずかしい の3段階（左側の人が選択）
- **再戦**: 待機者がいない場合、両者が「再スタート」を押すと再戦できます
- **交代**: 待機者がいる場合、負けた側が交代します

### 席と待機のしくみ

- 卓球台には「左席」「右席」の2席があります
- 先に入った人が左席、次の人が右席に入ります
- 3人目以降は待機列に入り、対戦を観戦できます
- 試合終了後、待機者がいる場合は負けた側が交代します

### 注意事項（無料プラン）

- **初回アクセス**: アクセスがない時間が続くとサーバーがスリープします。初回表示に30〜60秒かかることがあります
- **対戦中**: 両者のブラウザが開いている限り、サーバーはスリープしません
- **サーバー再起動**: サーバーが再起動すると、対戦状態はリセットされ、全員が名前入力画面に戻ります
- **復帰**: ブラウザを更新（F5）しても、10秒以内なら元の席に復帰できます

## 🚀 公開する人向け

初めての方でもGitHubとRenderを使って無料で公開できます。

### 必要なもの

- GitHubアカウント（無料）
- Renderアカウント（無料）

### 手順1: GitHubにリポジトリを作成

1. **GitHubアカウントを作成**  
   https://github.com にアクセスし、「Sign up」からアカウントを作成します（既にある場合はスキップ）

2. **新しいリポジトリを作成**  
   - GitHubにログイン後、右上の「+」→「New repository」をクリック
   - Repository name: `ping-pong-multiplayer`（任意の名前でOK）
   - Public を選択
   - 「Create repository」をクリック

3. **ファイルをアップロード**  
   - 作成されたリポジトリのページで「uploading an existing file」をクリック
   - 以下のファイルをドラッグ&ドロップでアップロード:
     - `package.json`
     - `server.js`
     - `render.yaml`
     - `public/index.html`（publicフォルダごと）
   - 下部の「Commit changes」をクリック

   または、コマンドラインに慣れている場合:
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/あなたのユーザー名/ping-pong-multiplayer.git
   git push -u origin main
   ```

### 手順2: Renderでデプロイ

1. **Renderアカウントを作成**  
   https://render.com にアクセスし、「Get Started」からアカウントを作成します

2. **GitHubと連携**  
   - Renderダッシュボードで「New」→「Blueprint」を選択
   - 「Connect a repository」でGitHubアカウントを連携
   - 先ほど作成したリポジトリを選択

3. **デプロイ**  
   - `render.yaml` が自動的に検出されます
   - 「Apply」をクリックしてデプロイを開始
   - 数分待つとデプロイが完了します

4. **URLを確認**  
   - デプロイ完了後、サービスのページに表示されるURLをクリック
   - `https://あなたのアプリ名.onrender.com` のようなURLでアクセスできます
   - このURLを友達に共有すれば、すぐに一緒に遊べます！

### 無料プランの制約

- **スリープ**: 15分間アクセスがないとサーバーがスリープします
  - スリープ中は最初のアクセス時に30〜60秒ほど起動時間がかかります
  - 対戦中は両者のブラウザが開いている限りスリープしません
- **メモリ管理**: サーバーはメモリ上で席や待機列を管理しています
  - サーバーが再起動すると、対戦状態は全てリセットされます
  - 再度名前を入力すれば、また遊べます
- **インスタンス数**: 必ず1インスタンスで動作させてください
  - 複数インスタンスになると、席の管理が正しく動作しません
  - `render.yaml` で `numInstances: 1` が設定されています

### トラブルシューティング

**デプロイが失敗する**
- `package.json` に `"engines": {"node": ">=18.0.0"}` が含まれているか確認
- Renderのログを確認してエラーメッセージを読む

**WebSocketが接続できない**
- ブラウザのコンソールを開いてエラーを確認
- httpsで接続している場合、自動的にwssが使われます

**ゲームが正しく動作しない**
- ブラウザのキャッシュをクリアして再読み込み
- 複数のタブで同じ名前で参加していないか確認

## 🛠️ ローカルで開発する場合

```bash
# 依存関係のインストール
npm install

# サーバー起動
npm start

# ブラウザで開く
# http://localhost:3000
```

2人で遊ぶには、2つのブラウザウィンドウまたは別のデバイスから接続してください。

## 🎯 技術仕様

- **サーバー**: Node.js + WebSocket (`ws` パッケージ)
- **クライアント**: バニラJavaScript + Canvas API
- **通信**: WebSocketでリアルタイム同期
- **ゲームロジック**: サーバー側で一元管理
- **状態管理**: メモリ上で管理（永続化なし）
